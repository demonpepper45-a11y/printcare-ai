# 架构草案

状态：本地原型已实现并有工程测试；向量检索与云部署为后续方案，尚未完成专业质量验收。

## 数据流

允许采集的官方来源 → 获取与解析 → 清洗和去重 → 标记机型和章节 → 切分 → SQLite 正文片段 → 内存 BM25 索引。后续再补向量与混合索引。

用户问题与会话 → 确认机型及必要条件 → 机型过滤 → 检索 → 组织上下文 → 模型回答 → 引用检查 → 展示与反馈。

## 技术选择

- Python：统一实现采集、检索和服务。
- FastAPI：问答及管理接口。
- Streamlit：第一版聊天与管理界面。
- Chroma：拟定向量存储，尚未接入。
- BM25：型号和错误码等关键词检索。
- SQLite：文档状态、反馈及索引版本记录。
- 模型 API：当前使用 DeepSeek 生成回答；中文 Embedding 尚未接入。
- Docker Compose：后续运行与部署。

## 模块边界

- ingestion：获取、解析、清洗，不调用回答生成逻辑。
- knowledge：文档、片段、来源元数据和索引版本。
- retrieval：机型过滤、术语归一化、BM25/标题加权、文档多样性；混合检索待实现。
- assistant：追问、多轮状态、生成和引用关联。
- api：请求校验与接口。
- web：页面展示。

正式并行开发前必须锁定问答接口字段、错误格式、文档标识和机型枚举。当前定义见 [接口与元数据定义](interfaces.md)（已供本地 API 使用）。

## 关键约束

文档元数据包括标题、URL、适用机型、主题、官方更新时间（可空）、采集时间、章节、内容指纹和启用状态。

索引构建支持新增、修改和停用，不能仅在数据库为空时索引。变更 Embedding 模型需要重建或隔离索引。不同开发工作区使用独立运行数据库。

正文、索引和用户数据分开管理。网页访问需限制来源、频率、大小和超时；采集失败可诊断。服务端保存密钥。管理接口上线前需要认证。日志避免记录敏感信息。
